# AGENTS.md

Agent-facing guidance for **ssl-VICE** — the RoboCup SSL robot-control stack (ROS2 Humble, Python, Dockerized).
[README.md](README.md) should be read before this file.

## Workspace layout

- ssl-VICE is a ROS2 colcon workspace
- Each folder under `src/` is an independent ROS2 package. 

## Packages (`src/`)

- `control` — robot control loop
- `control_unit` — centralizes information
- `grsim_messenger`, `hardware_messenger` — I/O to the grSim simulator / real hardware
- `gui`, `gui_interpreter` — ssl-gui bridge
- `main` — entrypoint / top-level launch orchestration
- `manual_command` — manual/teleop command path
- `movement`, `new_movement`, `movement_interfaces` — motion planning; `new_movement` appears to be an in-progress
  replacement for `movement` — confirm which is active before editing either
- `referee` — SSL referee/game-controller protocol integration
- `strategy` — high-level play/strategy logic
- `system_interfaces` — shared ROS2 msg/srv definitions
- `utils` — shared helpers
- `vision` — ssl-vision integration


## ROS2 default package structure

- \<pkg-name\> - Source code of the package (source folder)
- resource/ - All non-code files
- test/ - Tests for all source files of the package
- package.xml - Package metadata (name, dependencies, build type)
- setup.cfg - setuptools config
- setup.py - Used to create entrypoints to run the code with ROS2


## Coding standards

- Follow the [DRY principle of software engineering](https://en.wikipedia.org/wiki/Don%27t_repeat_yourself)
- Each file should have only one class
- Test folder structure should match its source folder structure
- Each source file should have its own test file
- Source folder should only have the necessary code for the nodes to run, anything else should be moved to other folders
- Constants
  - All constant values should be declared on the constructor of the class
  - If a constant value is used by more than one class it should be on a separate file to be imported by all users

## Do's

- Do edit code on the host — `src/` and `install/` are bind-mounted into the container (see `docker-compose.yml`).
- Do use `vice reload` after editing to recompile and relaunch, rather than manually restarting nodes.
- Do always run tests before committing to minimize breaking changes

## Don'ts

- Don't commit `build/`, `install/`, `log/`, `htmlcov/`, or `__pycache__/` — these are generated by colcon and pytest-cov
